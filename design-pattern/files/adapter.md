# 6. Adapter Pattern  
## هدف الگو Adapter
‫Adapter یک **الگوی ساختاری (Structural Pattern)** است که به ما اجازه می‌دهد:

**‫interface یک کلاس را به interface مورد انتظار تبدیل کنیم.**

وقتی دو بخش از برنامه با هم **ناسازگار** هستند، Adapter بین آن‌ها قرار می‌گیرد و نقش **مترجم** را بازی می‌کند.

---

## مسئله‌ای که این الگو حل می‌کند
در نرم‌افزارهای بزرگ معمولاً با این شرایط مواجه می‌شویم:

- ماژولی در سیستم جدید نوشته شده است، اما باید با یک **سیستم قدیمی (Legacy Code)** ارتباط برقرار کند.
- بخشی از سیستم باید از یک **کتابخانهٔ شخص ثالث** استفاده کند اما interface آن با ساختار پروژه ما سازگار نیست.
- دو کلاس داریم که **کار مشابهی انجام می‌دهند اما متدهای متفاوتی دارند**.

در این شرایط، تغییر دادن کلاس‌ها منطقی نیست، ویرایششان سخت است یا اصلاً دسترسی به سورس‌کد نداریم.  
بنابراین یک **Adapter** می‌سازیم.

---

# مثال کاربردی (به زبان ساده)

فرض کنید یک دستگاه در آمریکا با **ولتاژ 110 ولت** کار می‌کند.  
اما ما فقط یک پریز **220 ولت اروپایی** داریم.

پس باید یک **مبدل (Adapter)** داشته باشیم.

در کد:

- ‫EuropeanSocket خروجی 220V دارد.
- ‫USDevice انتظار 110V دارد.
- ‫Adapter بین این دو قرار می‌گیرد.

<div dir="ltr" align="left">

```python
class EuropeanSocket:
    def voltage(self):
        return 220


class USDevice:
    def power(self):
        print("Device running on 110V")


class Adapter:
    def __init__(self, socket):
        self.socket = socket

    def power(self):
        voltage = self.socket.voltage()
        print(f"Converted {voltage}V to 110V")


socket = EuropeanSocket()
adapter = Adapter(socket)

adapter.power()
```
</div>

خروجی:

Converted 220V to 110V

---

# تحلیل دقیق‌تر مثال
در این مثال:

- ‫EuropeanSocket → متدی به نام voltage دارد.
- دستگاه آمریکایی (USDevice) → متدی به نام power نیاز دارد.
- چون سازگار نیستند، ما Adapter را می‌سازیم تا:

**‫voltage → به power تبدیل شود**

این یعنی Adapter رابط جدیدی معرفی می‌کند که سیستم ما انتظار دارد.

---

# دلیل اصلی استفاده از Adapter
‫Adapter باعث می‌شود بدون اینکه بخش‌های موجود را تغییر دهیم بتوانیم آن‌ها را استفاده کنیم.

کاربردهای اصلی:

- سازگار کردن **کدهای قدیمی (Legacy)** با سیستم جدید
- استفاده از **کتابخانه‌های شخص ثالث**
- تغییر Interface بدون تغییر در کلاس‌های موجود
- ساده‌سازی ساختار سیستم و جلوگیری از وابستگی شدید (Loose Coupling)
- افزایش انعطاف‌پذیری سیستم با جدا کردن رفتار از interface

---

# انواع Adapter
به عنوان یک مهندس نرم‌افزار باید این را بدانید که Adapter فقط یک شکل ندارد.  

### ‫1. **Object Adapter** (رایج‌ترین و بهترین نوع)
با **Composition (ترکیب)** پیاده‌سازی می‌شود.

‫Adapter یک شیء از کلاس اصلی را در خود نگه می‌دارد.

مزیت:
- بهترین روش از نظر OOP  
- پشتیبانی از چند کلاس همزمان

مثال بالا از همین نوع است.

---

### ‫ 2. Class Adapter (با ارث‌بری)
Adapter از **کلاس اصلی ارث‌بری می‌کند**.

این مدل در زبان‌هایی مثل Python کمتر استفاده می‌شود.

دلیل:
- ارث‌بری چندگانه همیشه توصیه نمی‌شود
- انعطاف‌پذیری کمتر نسبت به object adapter

---

# نشانه‌هایی که به شما می‌گویند باید از Adapter استفاده کنید
اگر در پروژه به موارد زیر برخوردید، احتمالاً باید از Adapter استفاده کنید:

- کلاس A متدی دارد که کلاس B نمی‌تواند آن را استفاده کند.
- می‌خواهید دو سیستم را بدون تغییر در ساختار اصلی به هم متصل کنید.
- یک API خارجی دارد داده را در قالب متفاوتی برمی‌گرداند که سیستم شما انتظارش را ندارد.
- در حال رفرکتور کدهای قدیمی هستید و نمی‌خواهید کل پروژه را بازنویسی کنید.

---

#  مثال حرفه‌ای‌تر مخصوص Backend  
فرض کن دیتابیس قبلی سیستم JSON نگه می‌داده، اما سیستم جدید فقط کلاس‌های Python می‌خواهد.

<div dir="ltr" align="left">

```python
class LegacyDB:
    def fetch_user(self):
        return {"name": "ali", "age": 30}


class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age


class UserAdapter:
    def __init__(self, legacy_db):
        self.legacy_db = legacy_db

    def get_user(self):
        data = self.legacy_db.fetch_user()
        return User(name=data["name"], age=data["age"])


db = LegacyDB()
adapter = UserAdapter(db)
user = adapter.get_user()

print(user.name, user.age)
```

</div>

این کار باعث می‌شود:

- سیستم جدید User را دریافت کند  
- سیستم قدیمی همچنان تغییر نکند  
- هیچ جایی از سیستم متوجه این تغییر نشود  

---

# جمع‌بندی
Adapter Pattern یک ابزار بسیار مهم برای **سازگار کردن Interfaceها** است.

نکات کلیدی:

- مشکل ناسازگاری Interfaceها را حل می‌کند.
- نیازی نیست سیستم قدیمی را تغییر دهیم.
- با Composition پیاده‌سازی می‌شود (بهترین روش).
- استفاده در پروژه‌های واقعی بک‌اند بسیار رایج است.
- نقش مترجم بین دو سیستم را ایفا می‌کند.
